## 1. Research question, hypotheses and attribution

Master's thesis contribution = **Digital Twin + state-dependent reference Comfort Space + operational size tuning + Nav2-based multi-AMR evaluation framework**, **not a novel offset ellipse**, not new low-level obstacle avoidance, not verified human-subject comfort. Comfort from Neggers reference curves is a **literature-based predicted surrogate** calculated OFFLINE using the ACTUAL simulation interaction distance/direction.

Main falsifiable hypotheses:
- H1: too-large Comfort mask can hinder Nav2 multi-AMR mission completion in tight shared spaces.
- H2: reducing the mask can shorten detours and increase navigation feasibility but can degrade predicted Comfort by permitting closer human–AMR passes.
- H3: an INTERMEDIATE tested scale **may** provide a better navigation–predicted comfort balance than a fixed circular baseline or either tested extreme; **alpha 0.70/0.80 is a HYPOTHESIS, not a predetermined winner**.
- H4 (requires an additional ablation): if the thesis claims ***different state-wise size settings*** contribute beyond fixed global alpha and shape changes, test a separately preregistered B3-statewise policy with distinct state alphas vs the same-template global-alpha controls.

If the actual result favors alpha 0.60 or 0.90 or no statistically distinguishable policy, REPORT THAT. Do not tune geometry, reward weights, C*, aggregation, seed lists, inclusion criteria, or plot axes after seeing which alpha wins.

## 2. The ONE invariant control/measurement chain

For **every** experimental policy, every AMR (AMR1, a1, a2):
`simulated tracked person pose+heading+ground-truth state → B1/B2/B3 analytical Comfort Filter Mask (when enabled) → Nav2 costmap → NavFn global planner / DWB local controller / built-in behavior recovery → Collision Monitor physical safety layer → differential-drive robot`.

- NO custom `comfort_gate` running in the velocity chain, NO comfort-yield HOLD, evasion/sidestep, custom backoff/off-lane, custom direct `cmd_vel` or `traffic_rule`. `control.mode: nav2_only`, `comfort_space.yield.enabled:false`, `yield.evade.enabled:false`, `recovery.backoff.enabled:false`, `recovery.off_lane.enabled:false`, `traffic_rule.enabled:false`, `comfort_space.costmap.buffer_width:0.10`.
- Keep **Nav2 default behavior_server recovery ON**, collision monitor ON (same zone, thresholds, braking), lidar/obstacle safety ON, speed limits, footprint, mask cost 98 (finite, not lethal), `comfort_space.min_radius=0.30m`, map/localization/simulator hardware unchanged across conditions. Verify actual per-robot ROS graph at trial start and record `control.problems=[]`, `gate_seen=false`, `cmd_vel_safe` from Nav2 only, `cmd_vel` from collision_monitor only.
- Main policy-comparison mode uses `perception.source=tf` and `humans.state_source=ground_truth` to isolate sizing, NOT validated LiDAR worker classification; sensor-mode is separate optional work.
- Every policy has the SAME physical world, worker movement schedule, robot task/starts/goals, planner/controller settings and safety fields for a matched seed. Any scenario/geometry modification must be regenerated for ALL policies. A source/config/geometry hash, controls hash, actual extents and ROS graph must be stored per launch.

## 3. Common policy/normalization definitions

Use **fixed common design anchor** `R_ref=0.95m` from the 2026-11-27 preliminary Nav2-only Stage 1. Final Stage 1 tests whether it qualifies; if not, honestly report that and do not silently alter B2 or the Stage 2/3 conditions after viewing final data. A separately preregistered revision is needed to change R_ref.

Policies:
- `B1`: Comfort filter OFF; other Nav2 and safety unchanged.
- `B2`: static **circular** Comfort Space radius `0.95m` (same reference across all stages).
- `B3(alpha)`: same adopted asymmetric offset-ellipse reference shape for each human state, with one common alpha multiplied onto ALL three F/S/R extents in that state; no separate F/S/R tuning, no shape/geometry invention. Let `E_state(1)=R_ref*E_raw_state/max(E_raw_state)` and `E_state(alpha)=alpha*E_state(1)`. Freeze raw template state F/S/R (engaged `0.80/0.70/0.60`; stationary `0.80/0.90/1.05`; moving at 1.0m/s reference `1.20/0.90/0.90`), moving heading=velocity, stationary/engaged heading=body facing. Freeze speed dependence to `moving_reference_speed_mps:1.0` (gain 0 in grid). Reject `min_radius` clipping and assert geometry/scale exactly.
- NEW Stage 3 five conditions: `B2_circle_0.95`, `B3_alpha_0.60`, `B3_alpha_0.70`, `B3_alpha_0.80`, `B3_alpha_0.90`. These are **global/common-alpha tests on state-specific REFERENCE SHAPES**. They DO NOT alone demonstrate independently optimized state-wise alphas.
- If adding H4 ablation, `B3_statewise` must be separately declared/frozen before Stage 3 data. Engineering fallback e.g. `engaged=0.60 (EN-R observed)`, `stationary=0.80 (conservative unvalidated fallback)`, `moving=0.80 (conservative unvalidated fallback)`; explicit tentative vs supported provenance. ## 6. Fixed primary/secondary endpoints and winner selection (pre-register)

**Primary Stage 3:** `trial_joint_success = all AMRs finish assigned missions AND no human–AMR physical contact AND all required valid encounters meet predicted comfort >=5.0`. Publish the exact per-encounter eligibility definition (true closest distance and human state/direction; exclude nothing for poor score). If a needed comfort score is unavailable/out-of-reference, label `NOT_SCORABLE`, report coverage and perform a sensitivity analysis; do not auto-count it as a comfort pass. Also report `safe_system_completion` separately so a completed mission with contact cannot be called safe.

**Secondary (predeclare):** system/Nav2 completion of all AMRs (count/n, Wilson CI), per-AMR completion, **any human–AMR contact count/duration**, Collision Monitor protective stops (terminal/transient), Nav2 abort/no-progress/deadlock (no gate-derived mechanism), travel time per AMR (success-only + *capped all-trial* summary to avoid survivorship bias), path length, hold/idle seconds (NOT custom "yield time"), global/local replan count, realized closest center and footprint-edge clearance, min/10th-percentile and per-state predicted comfort, number of eligible scored encounters, policy coverage and speed/reference-domain flags. Confidence intervals and raw n for every endpoint. Never use fewer-than-30 silently.

**Decision rule before main data:** Safety first (contact trials <=1/30 as empirical safety screen; signal uncertainty with CI), navigation completion >=0.80, trial joint success >=0.80, coverage of required encounter scoring explicitly sufficient; if none qualify, **NO ACCEPTABLE SCALE**, not force 0.70/0.80. Among qualifying cases select highest observed trial-joint rate; if tied or indistinguishable within uncertainty, report **Pareto-feasible/tied range** and use minimum capped mission time as *predeclared tie-break*. Report median travel/path with dispersion, compare B2 with each B3 using matched-seed comparisons (McNemar for binary outcomes, paired bootstrap CI / appropriate rank tests for numeric) and correct for multiple comparisons (Holm or clearly exploratory). Do not label an alpha "statistically best" without support. Plot navigation + predicted comfort + joint, time and contact across all five cases. Sensitivity at C*=4.5/5.5; the preference may change.

**Separate contribution warning:** The five-case sweep uses a COMMON alpha with *state-dependent reference F/S/R ratios*. It supports "systematic policy-scale selection" but does NOT independently establish "different optimized alpha for each human state". If the title/conclusion asserts state-specific dynamic size selection, add an optional registered B3 statewise ablation as the **sixth** case (another 30 launches); distinguish identified engaged scale and conservative unvalidated stationary/moving fallbacks.
